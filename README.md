# Кант — шаблон сайту майстерні меблів на замовлення

MVP для майстерні корпусних меблів (кухні, шафи-купе, гардеробні, передпокої, комоди, тумби, стелажі) з виїздом на замір. Клієнт збирає виріб у **3D-конфігураторі**: розміри, секції, двері, матеріали, кольори, наповнення. Він одразу бачить орієнтовну ціну за відкритою формулою й надсилає заявку з фото. Власник у кабінеті призначає замір, після нього вводить остаточну ціну, строк виготовлення й дату монтажу. Клієнт бачить усі оновлення за приватним посиланням.

Шаблон розрахований на одну майстерню: окремий екземпляр і окрема база. Назва, контакти, місто, прайс, палітра матеріалів, строки, гра й персонажі налаштовуються в кабінеті без коду. Бриф, з якого зроблено проєкт, — [docs/BRIEF.md](docs/BRIEF.md).

## Стек

Nuxt 4.6 (SSR, серверні маршрути) · Vue 3.5 `<script setup lang="ts">` + Pug + SCSS-токени · Pinia · Three.js 0.187 + TresJS 5.11 + Cientos 5.11 · PostgreSQL (postgres.js), локально PGlite · sharp · zod · pnpm.

Версії сумісні: Cientos 5.11 вимагає `@tresjs/core ^5.9.1` і `vue >=3.5.17`, Core 5.11 — `three >=0.133`. Модуль `@tresjs/nuxt` не використовується (тягне `@nuxt/ui`), TresJS підключено напряму через `templateCompilerOptions`. Основа — шаблон клінінгу «Прибрано» (`../cleaning-service`), перероблений під меблі.

## Швидкий старт

```bash
pnpm install
cp .env.example .env   # впишіть свій NUXT_ADMIN_PASSWORD (мінімум 10 символів) і NUXT_PUBLIC_SITE_URL
pnpm dev               # http://localhost:3000 (або --port 3020)
```

Окремий сервер бази не потрібен: без `DATABASE_URL` дані лежать у вбудованій PostgreSQL-сумісній PGlite у `.data/pglite` (або в `DATA_DIR`). Зовнішній PostgreSQL потрібен лише на Vercel. Деталі й бекапи — у [docs/DEPLOY.md](docs/DEPLOY.md).

| Команда | Що робить |
|---|---|
| `pnpm dev` | розробка |
| `pnpm build` / `pnpm preview` | збірка й запуск `.output` |
| `pnpm typecheck` | vue-tsc разом із Pug-шаблонами (клієнт, сервер, shared) |
| `pnpm test` | юніт-тести формули й схеми заявки |
| `pnpm smoke [url]` | наскрізна перевірка API на запущеному екземплярі (вигадані дані; тимчасово змінює прайс, гру й пароль і повертає їх, після себе видаляє заявку) |

### Клієнтський шлях

1. **Конфігуратор** (`/calculator`). Тип меблів обирається з картки зі ставкою «від…», нижче показано, що входить і що ні, та строк виготовлення.
   - Для корпусних меблів задаються ширина, висота й глибина в мм (степпери з межами для кожного типу й ручним вводом), секції та двері-купе.
   - Для кухні: форма (пряма, кутова, П-подібна), довжина низу й верху, острів.
   - Далі матеріали фасадів і корпусу, кольори з палітри майстерні, клас фурнітури, наповнення й опції з лічильниками, монтаж, демонтаж і складна форма.
   - 3D-модель і ціна оновлюються одразу.
   - Для «Інше» замість параметрів пишеться опис, а ціна — «після фото».
2. **Кошик** (`/cart`). Можна додати кілька виробів. Однакові позиції об'єднуються, різні налаштування лишаються окремими рядками. Є кількість, редагування, видалення зі «Скасувати» й порожній стан. Відома сума й позиції з ручною оцінкою показані окремо.
3. **Оформлення** (`/checkout`). Поля форми:
   - ім'я, телефон +380, адреса обʼєкта;
   - «за містом», доставка, поверх і вантажний ліфт (впливають на доплати);
   - бажані дата й час заміру (час доступний лише після дати);
   - до 3 фото чи ескізів, з прев'ю, повтором і видаленням; для «Інше» хоча б одне обов'язкове;
   - коментар і згода на обробку даних.

   Коди домофона й ключі форма не збирає, онлайн-оплати немає. Помилки показуються біля полів. Чернетка й кошик переживають перезавантаження.
4. **Відправка.** Успіх показується лише після запису в базу. Повтор після збою з тим самим ключем повертає ту саму заявку.
5. **Сторінка заявки** (`/order/<токен>`). Показує склад, статус, попередній розрахунок, дату заміру, остаточну ціну, строк виготовлення, дату монтажу й умови доставки. Посилання можна скопіювати. Сторінка сама оновлюється раз на хвилину. Тут же є необов'язкова гра «Відшліфуй дошку».

### Кабінет `/admin`

Розділи кабінету: «Заявки», «Прайс», «Майстерня», «Гра», «Персонажі», «Доступ».

- **Список заявок:** пошук, фільтри за статусом, типом меблів і періодом, кнопка «Заміри на тиждень», оновлення.
- **Картка заявки:** контакт, доставка й поверх, приватні фото, склад із розрахунком по кожній позиції, побажання, історія, приватна нотатка.
- **Статуси:** нова → замір → погоджена → виконана / скасована.
  - «Замір» не ставиться без дати заміру.
  - «Погоджена» не ставиться без остаточної ціни й строку виготовлення.
- **Видалення** заявки разом із фото проходить через діалог підтвердження.

### Безпека й дані

- Сервер заново рахує заявку за поточним прайсом і зберігає знімок прайсу та розрахунку.
- Origin перевіряється на всіх мутаційних запитах. Обмеження запитів зберігається в БД, тож працює й на serverless.
- Пароль хешується через scrypt. Сесія — httpOnly SameSite=Strict cookie, у базі лежить лише хеш токена. Після зміни пароля всі сеанси закриваються.
- Фото: формат визначається з вмісту, зображення зменшується до 1600 px, EXIF і GPS видаляються. Публічних адрес у фото немає.
- Публічне API не віддає телефон, адресу, фото й нотатку.
- Політика зберігання й видалення даних — [docs/DATA-POLICY.md](docs/DATA-POLICY.md).

Формула — [docs/PRICING.md](docs/PRICING.md). Адаптація й витрати — [docs/ADAPTATION.md](docs/ADAPTATION.md). Обмеження — [docs/LIMITATIONS.md](docs/LIMITATIONS.md). Ліцензії — [LICENSES.md](LICENSES.md).

## 3D

### Конфігуратор (`app/three/furniture.ts`)

Модель будується параметрично з конфігурації за кілька мілісекунд, тож файли моделей не завантажуються.

- **Корпусні меблі:**
  - корпус, цоколь, задня стінка й перегородки секцій;
  - розсувні двері-купе на двох напрямних з алюмінієвими профілями (кнопка «Відкрити» розсуває їх і робить напівпрозорими);
  - розпашні двері, що повертаються на петлях;
  - висувні ящики й корзини;
  - полиці, штанги з одягом, підсвітка, дзеркальні фасади, ручки.
- **Кухня:**
  - модулі по ~60 см, стільниця, цоколь;
  - кутова й П-подібна форма (бічні ряди вздовж стін), верхні модулі від кута;
  - мийка зі змішувачем і варильна поверхня за вирізами, острів, підсвітка під верхом.
- Розмірні лінії з підписами в мм; розмір підпису залежить від розміру виробу.
- Камера кадрує виріб під його розмір. Обертати можна пальцем і мишею, з обмеженнями камери й кнопкою скидання ракурсу. Зміна типу меблів анімована пружиною: стара модель зменшується, нова з'являється.
- Рендер іде лише на вимогу (`on-demand`): кадри малюються під час взаємодії й анімацій. DPR обмежено до 1,75. Тінь будується в сцені.
- Без WebGL показується SVG-схема й пояснення, а розміри й ціна працюють як завжди.
- Під сценою чесно підписано: «Візуалізація орієнтовна, остаточний проєкт — після заміру».

### Персонажі (`app/three/characters.ts`)

| Персонаж | Тип | Пізнаваний за |
|---|---|---|
| Шуруп | Кухня | корпус шуруповерта, рукоятка, акумулятор, патрон і біта, що обертається |
| Метрик | Шафа-купе | кругла рулетка з гумовим ободом, стрічка з поділками й гачком на підлозі |
| Бульбик | Гардеробна | алюмінієвий рівень на ніжках, колбочка з бульбашкою, що рухається |
| Тук | Передпокій | дерев'яна ручка з гумою, сталева голова з бойком і цвяходером |
| Грифель | Комод, тумба, стелаж | шестигранний столярний олівець, заточений конус, грифель |
| Скринько | Інше | ящик з інструментами, ручка, замки, викрутка |

Персонажі мають обличчя, руки, привітання рукою, рідкісне кліпання й дихання. Репліки написано заздалегідь, і вони прив'язані до проєкції точки над головою. Є reduced motion, пауза поза екраном, постер без WebGL і повтор після помилки.

### Гра «Відшліфуй дошку»

Стара фарба лежить на CanvasTexture за UV лицьової площини дошки. Пензель знімає фарбу через raycast, але лише коли першим влучанням є саме фарба: під час повороту дошка перекриває її власною геометрією. Режими «Шліфувати» й «Обертати» розділені, прогрес показується, є «Пофарбувати знову». У кабінеті гру можна вимкнути, запустити без знижки або з бонусом; бонус дається один на заявку й погашається вручну.

## Дизайн

- **Палітра:** теплий «папір» `#f4efe7`, ink `#221d18`, акцент «Горіх» `#8a4b22` (ще три в кабінеті: «Шавлія», «Чорнило», «Глина»), латунь `#c9962e` для бейджів. Є світла й темна теми.
- **Шрифти:** Literata (заголовки) + Onest (текст), обидва з кирилицею.
- **Логотип** — фасад шафи з кантом-кромкою.
- **Figma-файл не створено** в цій ітерації (див. «Не перевірено / не зроблено»).
